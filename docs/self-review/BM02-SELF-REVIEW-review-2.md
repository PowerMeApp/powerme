## 5 most important findings

1. **F01 / F25 — Scope and flow traceability cannot be established from the repo (High).** The registration form, SRS, SDD, Logical ERD and activity diagrams are not present; only 3 FR ids exist anywhere. Checks 1, 2 (FR part), 3 (ERD side) and 5 (activity diagrams) are reported as not verifiable rather than guessed.
2. **F18 / F19 — STM-1 is only partially executable (High).** 6 of 22 transitions plus the hard-cap branch have no trigger; `pending`, `stopping`, `failed` can never be persisted, and `review` (where every conflicting session ends) has no exit because the operator-resolve transition (#17) is never emitted and `reviewed_by/at` are never written.
3. **F26 / F27 — Core business flows are absent (High).** No pricing, wallet debit, invoice or VNPay path after `reconciled` (`total_cost_vnd` never set; 21 of 32 tables never touched by code, F17), and no driver-initiated start (RemoteStart / app QR) or other downstream commands.
4. **F31 — Architecture diagram vs code (High).** Of the 8 modules and the Caddy / Redis / BullMQ / Socket.IO infrastructure drawn in the package diagram, only gateway, sessions and reconciliation exist (plus an undocumented console); dependency rules are also violated in code (F33) and two status documents describe the repo as it was before the code existed (F36).
5. **F37 / F21 — Security and pillar lifecycle design not implemented (High).** Basic Auth / Security Profile 2 is not enforced (any known serial is accepted, the gateway listens on all interfaces), and the STM-3 lifecycle uses only two of six values, with no guard against `disabled` / `decommissioned` pillars reconnecting.
